# StarsHash

Мини-апп Telegram: майнинг звёзд, три игры (Краш, ПВП, Кейсы), ежедневный
бонус, задания, таблица лидеров и реферальная программа. Три языка —
русский, английский, украинский.

## Что выкладывать

```
starshash/
  index.html   ← сама программа
  admin.html   ← админка: дашборд, заявки на вывод, игроки
  img/         ← картинки: аватарки соперников и баннеры игр
```

Оба нужны: `index.html` ссылается на `img/` относительными путями.

Раньше картинки были вшиты в HTML одним файлом. Так удобнее отдавать, но
дорого при повторных открытиях: HTML браузер перепроверяет каждый раз, и
человек качал весь мегабайт заново на каждом заходе. Теперь HTML весит
348 КБ (88 КБ в сжатом виде), а картинки лежат отдельно и кэшируются
навсегда — в имени каждого файла отпечаток содержимого, поэтому изменённая
картинка получает новое имя и подхватывается сама.

Настройте на хостинге долгий кэш для `img/` — например,
`Cache-Control: public, max-age=31536000, immutable`. Для Vercel это уже
описано в `vercel.json`: год для картинок, ноль для `index.html`, чтобы
новая версия доходила до людей сразу. При выкладке укажите корнем папки
`starshash` — тогда `vercel.json` подхватится сам.

## Если нужен один файл

```bash
node tools/inline-images.js путь/куда.html
```

Соберёт HTML со всеми картинками внутри — для предпросмотра или когда файл
отдают одним куском. Склейка побайтно совпадает с тем, что было до выноса.

Обратная операция, после добавления новой встроенной картинки:

```bash
node tools/split-images.js
```

## Баннеры игр

Надписи на баннерах Краша, ПВП и Кейсов **нарисованы внутри картинок**, а не
выведены текстом, поэтому под каждый язык лежит свой файл: `crash-ru`,
`crash-en`, `crash-uk` и так же для `pvp` и `kase`. Переключение — правилами
`html[lang="en"]` и `html[lang="uk"]`; русский служит запасным, если языка
нет в списке.

Приложение рисует поверх баннеров живые элементы, и художнику надо про них
знать:

- **Краш** — анимированная ракета со шлейфом, кривая роста и текущий
  множитель. Место под множитель — пустая рамка справа снизу; писать туда
  число в картинке нельзя, оно перекроется живым.
- **ПВП** — лента соперников с настоящими лицами и долями. Она закрывает
  правую половину баннера целиком, поэтому нарисованные там бойцы не видны.
- **Кейсы** — только слабое свечение, картинка видна как есть.

## Бот и реферальная ссылка

Бот — `@starshashx_bot`. Приглашение выглядит так:

```
https://t.me/starshashx_bot?startapp=ref_<id>
```

Именно `?startapp=`, а не `?start=`: второй уходит боту в переписку, до
приложения метка не доходит и приглашение теряется молча. Такая ссылка
работает, когда у бота назначен главный мини-апп: BotFather → бот →
Settings → Mini Apps → Configure Mini App.

Если вместо главного делать отдельный через `/newapp`, впишите его короткое
имя в `ПРИЛОЖЕНИЕ` (модуль `Ref` в `index.html`) — ссылка станет
`t.me/starshashx_bot/<имя>?startapp=ref_<id>`, метка передаётся так же.

Токен бота в файлах приложения не нужен и не должен там появляться:
`index.html` отдаётся браузеру целиком, его прочитает любой. Токен живёт
только в переменных окружения сервера.

## Сервер

Пока баланс лежит в телефоне, он принадлежит игроку: веб-инспектор
Telegram Desktop открывается в два клика. Поэтому деньги живут в базе, а
приложение показывает то, что отдал сервер.

```
starshash/
  api/starshash.js   ← функция Vercel: вся работа с деньгами
  api/bot.js         ← бот: приём оплаты звёздами и настройка вебхука
  db.sql             ← схема базы, выполнить в Supabase
```

`db.sql` безопасно выполнять повторно — всё через `if not exists`. После
обновления, добавившего заявки на вывод, прогоните его ещё раз: он заведёт
таблицу `sh_withdrawals`, ничего не тронув в остальном.

Кто пришёл, определяется по подписи `initData` — HMAC токеном бота.
Подделать чужой `tg_id` нельзя, подпись не сойдётся. Отдельной регистрации
нет: человек открывает приложение и уже заведён.

Через сервер идёт всё, что двигает деньги: баланс и майнинг, вложение,
ежедневный бонус, задания, Краш, ПВП, Кейсы, пополнение счётом Telegram,
заявка на вывод и её история. Клиент показывает то, что вернул сервер, и
сам баланс не считает. Пока сервера нет (вне Telegram или до настройки
переменных), приложение работает из памяти телефона, как раньше, — поэтому
проверки в браузере видят прежнее поведение.

Баланс из памяти телефона в базу не переносится: у каждого на сервере он
начинается с нуля. Так и задумано — деньгам в телефоне доверять нельзя.

### Пополнение криптой

Второй способ пополнения — через **@CryptoBot**, тем же путём, что в
«шарке»: сервер выписывает счёт его ключом, а зачисляет не по вебхуку, а
ленивой проверкой. Приложение раз в три секунды спрашивает статус, сервер
идёт в `getInvoices` своим ключом и, увидев `paid`, начисляет звёзды. На
serverless это надёжнее вебхука — не нужно ловить сырое тело и сверять
подпись. Повторная проверка ничего не удваивает: номер счёта уже лежит в
журнале.

Цена берётся из лесенки — той же, что нарисована в приложении:

| ★ | GRAM | к оплате, USDT |
|---|---|---|
| 50 | 1 | 1.33 |
| 100 | 2 | 2.66 |
| 200 | 3.7 | 4.92 |
| 500 | 9 | 11.97 |
| 1 000 | 18 | 23.94 |
| 2 500 | 45 | 59.85 |
| 5 000 | 89 | 118.37 |

Своя сумма считается по этой же лесенке, между соседними пакетами тянется
прямая. Набор `server` сверяет таблицу в приложении с серверной: разойдись
они — в счёте оказалось бы не то число, что человек видел на экране.

Лесенка записана в GRAM, а счёт выписывается в USDT: **у Crypto Pay нет
актива `GRAM`** — на попытку выписать счёт в нём приходит
`UNSUPPORTED_ASSET (400)`, даже если GRAM лежит в кошельке @CryptoBot.
Поэтому цена переводится по курсу `КУРС_USDT` — одно число в
`api/starshash.js` и такое же в `index.html`. Меняется курс — правятся оба,
и набор `server` следит, чтобы они не разъехались: разойдись они, на экране
было бы одно число, а списалось другое.

**Чем платят, задаётся переменной `SH_CRYPTO_ASSET`, и без неё счёт не
выписывается вовсе.** Имя сверяется со списком `КРИПТО_АКТИВЫ` до похода в
@CryptoBot: на неизвестный актив сервер отвечает `bad_asset` и перечисляет
разрешённые, иначе человек увидел бы пустой отказ от чужого 400. Пока
переменная не задана, приложение честно говорит «оплата криптой пока
недоступна».

Доля пригласившему — те же 5%, что и при оплате звёздами; начисляется
здесь же, потому что только тут известно, что оплата настоящая.

### ПВП

Вход от 30 ★, соперники приносят в банк от 65 до 187 ★ на троих-пятерых.
Победитель выбирается взвешенно: шанс равен доле в банке, и никак иначе —
подкрутки нет. Раунды всё равно чаще уходят соперникам просто потому, что
их несколько, а игрок один: на минимальном входе доля игрока около пятой,
столько же и побед. Числа продублированы в приложении и на сервере, и
набор `server` сверяет обе копии — разойдись они, банк на экране менялся
бы в момент розыгрыша, и это игрок справедливо читает как подвох.

Состав раунда сервер называет в ответ на вход, а не перед розыгрышем.
До входа за столом видны собирающиеся соперники, после — окончательный
состав, и дальше банк не меняется.

### Вывод

Вывод не мгновенный. Игрок оставляет заявку — сервер тут же снимает сумму
с баланса (комиссия внутри) и держит её в удержании, чтобы те же звёзды
нельзя было заодно проиграть. Заявку разбирает человек-админ. Выплата
закрывает заявку, отказ возвращает сумму на баланс. Историю своих выводов
игрок видит в шторке «Вывести».

Действия сервера (`POST { action, initData, … }`): `state`, `invest`,
`bonus`, `task`, `topup`, `crash_bet`, `crash_settle`, `case_open`, `pvp`,
`top`, `withdraw`, `withdrawals` (свои заявки). Только для админов:
`admin_dash`, `admin_withdrawals`, `admin_decide`, `admin_users`,
`admin_adjust`, `admin_ban`.

## Админка

```
starshash/admin.html   ← панель управления, открывается по /admin.html
```

Отдельная страница, а не раздел приложения: списки и графики внутри
мини-аппа читать невозможно, а так панель открывается и с настольного.
В профиле приложения при этом остаётся короткий список заявок — чтобы
выплатить, не выходя из телефона.

Три раздела:

- **Дашборд** — игроки, новые, активные за сутки; сколько лежит на
  балансах и вложено в мощность; пополнения, выводы, ставки, выигрыши и
  казна с игр за 30 дней; семь графиков по дням.
- **Заявки на вывод** — с вкладками по состоянию, кнопки «Выплатить» и
  «Отклонить». Отказ возвращает сумму игроку.
- **Игроки** — поиск по имени или `tg_id`, балансы и игровые итоги,
  ручное начисление и списание с причиной в журнале, закрытие доступа.

Кто админ, решает сервер по `SH_ADMIN_IDS` — страница только показывает
то, что он отдал. Открыть её может кто угодно, но без подписи Telegram и
без права она не покажет ничего: в ответ придёт `forbidden` вместе с
вашим `tg_id`, чтобы было что вписать в переменную.

### Вход в панель

Внутри Telegram подпись берётся из мини-аппа сама. В обычном браузере
вход идёт через **Telegram Login Widget**, а он требует, чтобы у бота был
задан домен:

```
BotFather → /setdomain → выбрать бота → прислать адрес сайта
```

Без этого кнопка входа не появится — сам виджет её не покажет.

Правка баланса вручную пишется в журнал видом `admin` вместе с причиной:
деньги, появившиеся без следа, потом не с чем сверить.

Настроить (Vercel → Settings → Environment Variables):

| переменная | что это |
|---|---|
| `SH_SUPABASE_URL` | адрес проекта Supabase |
| `SH_SUPABASE_SERVICE_ROLE_KEY` | service-role ключ, секрет — в браузер не попадает |
| `SH_BOT_TOKEN` | токен бота от @BotFather |
| `SH_ADMIN_IDS` | `tg_id` админов через запятую |
| `SH_APP_URL` | адрес мини-аппа — для кнопки в переписке с ботом |
| `SH_SETUP_SECRET` | пароль к `/api/bot?setup=…`, чтобы вебхук не переставил чужой |
| `SH_CRYPTOBOT_TOKEN` | ключ @CryptoBot — для пополнения криптой |
| `SH_CRYPTO_ASSET` | чем платят: `USDT` (цены в таблице — под него), `TON` и т. п. Без неё крипта выключена |

### Оплата звёздами

Счёт выписывает `starshash.js`, а зачисляет **бот** — и только когда
Telegram сам сообщит об оплате. Слово телефона «я заплатил» не стоит
ничего, поэтому приложение к зачислению не причастно.

Telegram повторяет доставку события при любой заминке с ответом, поэтому
зачисление опирается на номер чека: платёж с уже встречавшимся номером
пропускается. Там же начисляется доля пригласившему — только здесь видно,
что пополнение настоящее.

Разовая настройка после выкладки: открыть в браузере
`https://<адрес>/api/bot?setup=<SH_SETUP_SECRET>`. Пропишет вебхук.

Пока переменные не заданы, функция отвечает `not_configured`, и приложение
работает по-старому, из памяти телефона: выкладка не ломает то, что уже
есть.

Экономика продублирована в `api/starshash.js` намеренно — присланному
телефоном числу верить нельзя, ставку сервер считает сам. Набор `server`
сверяет обе копии, чтобы они не разъехались.
