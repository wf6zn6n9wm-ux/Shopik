# SHARK — Telegram Mini App

Игры на звёзды (краш, рулетка, **PVP-джекпот**), магазин подарков,
рефералы и вывод денег с **ручным подтверждением** в Telegram.

Раздел «Задания» удалён. Деньги (грн) начисляются за приглашённых друзей;
вывод — только после вашего ручного подтверждения.

## Стек

- **Фронтенд:** статический `index.html` (Telegram WebApp SDK). Вне Telegram
  или при ненастроенном бэкенде — работает как локальное демо.
- **Бэкенд:** Vercel serverless (Node) — `api/shark.js` (API) и `api/bot.js`
  (вебхук бота).
- **БД:** Supabase (PostgreSQL) через REST. Вся логика денег/звёзд — на сервере.

## Деплой (Vercel)

Отдельный проект Vercel с **Root Directory = `shark`**.

### 1. Supabase
1. Создайте проект на supabase.com.
2. SQL Editor → выполните `schema.sql` (безопасно перезапускать при
   обновлениях — все таблицы через `create table if not exists`).
3. Скопируйте **Project URL** и **service_role** ключ (Settings → API).

### 2. Бот (@BotFather)
1. Создайте бота, получите токен.
2. Настройте кнопку Mini App (Menu Button → URL вашего деплоя).
3. В `api/bot.js` при необходимости поправьте `DEFAULT_APP_URL`, а в
   `index.html` — `BOT_USERNAME` (username бота для реф-ссылок).

### 3. Переменные окружения (Vercel → Settings → Environment Variables)
| Переменная | Значение |
|---|---|
| `SHARK_SUPABASE_URL` | Project URL из Supabase |
| `SHARK_SUPABASE_SERVICE_ROLE_KEY` | service_role ключ (секрет!) |
| `SHARK_BOT_TOKEN` | токен бота |
| `SHARK_ADMIN_IDS` | ваши tg_id через запятую (кому приходят заявки на вывод) |
| `SHARK_APP_URL` | URL Mini App (напр. `https://<project>.vercel.app/`) |
| `SHARK_ADMIN_PANEL_IDS` | tg_id, кому доступна админ-панель. **Не задана — панель закрыта для всех.** |

> `SHARK_ADMIN_IDS` и `SHARK_ADMIN_PANEL_IDS` — разные списки. Первый отвечает
> только за уведомления в Telegram (заявки на вывод, покупки подарков), второй —
> за доступ к панели и ручному начислению звёзд. Добавить человека в первый ради
> уведомлений не открывает ему второй.

> Можно и без префикса `SHARK_` (`SUPABASE_URL`, `BOT_TOKEN`, `ADMIN_IDS`, …) —
> если у вас в проекте нет других сервисов с теми же именами.

### 4. Привязать вебхук бота
После деплоя один раз откройте в браузере:

```
https://<ваш-домен>/api/bot?setup=1
```

## Как работает вывод денег

1. Пользователь создаёт заявку → деньги сразу списываются с баланса (заморозка).
2. Вам (в `SHARK_ADMIN_IDS`) приходит карточка с кнопками **✅ Подтвердить / ❌ Отклонить**.
3. Выплату вы делаете **вручную** (карта/USDT), затем жмёте ✅ — пользователь
   получает уведомление.
4. ❌ Отклонить — деньги **возвращаются** на баланс пользователя.

Автоматических выплат нет.

## Админ-панель

Вход появляется в профиле только если сервер вернул `isAdmin` — то есть ваш
tg_id есть в `SHARK_ADMIN_PANEL_IDS`. Клиент это право не выводит сам.

- **Сводка** — игроки, балансы, оборот за 7 дней, ожидающие выводы.
- **Игроки** — поиск по имени/нику/id, сортировка, страницы по 30.
- **Баланс** — начисление и списание ⭐ на свой аккаунт через тот же
  `shark_apply_ledger()`, что и любое другое движение средств, с ключом
  идемпотентности. Гривны начислять нельзя (они выводятся), чужой баланс из
  панели не трогается.

Аккаунт из `SHARK_ADMIN_PANEL_IDS` не попадает в один раунд PVP с живыми
игроками: `pvp_join` отклоняет вход причиной `round_mixed`. Боты не в счёт.

После изменения переменных окружения Vercel **не применяет их к уже собранным
деплоям** — нужно нажать Redeploy.

## Безопасность

- Личность — по подписи Telegram `initData` (HMAC токеном бота); `tg_id` из тела
  запроса не доверяется.
- Балансы = сумма леджера (`shark_ledger`), движение средств — через атомарную
  идемпотентную функцию `shark_apply_ledger` (нельзя списать в минус или начислить
  дважды).
- Звёзды **не конвертируются** в деньги ни одним действием.
- Исходы игр (рулетка, краш, PVP) считает сервер; краш и PVP —
  provably-fair (хэш seed фиксируется, seed раскрывается после раунда).

## PVP-джекпот (общие раунды)

Игроки скидываются звёздами в **общий банк одного раунда**, победитель
забирает всё; шанс победы = доля ставки в банке. Комиссия дома `PVP_RAKE`
(5%) — ожидание игрока = ставка × 0.95, как честная лотерея с рейком.

**Как устроено на serverless (без вебсокетов):**
- Один активный раунд за раз (`shark_pvp_rounds` + `shark_pvp_bets`).
- Первая ставка запускает отсчёт `PVP_DURATION_S` (15 с) и подсаживает 1–3
  ботов для оживления. Пока идёт отсчёт — заходят другие живые игроки.
- Клиент **опрашивает** `pvp_state` (~1.5 с) и показывает живой банк,
  участников и таймер.
- **Ленивый резолв:** когда таймер истёк, ближайший запрос `pvp_state`/
  `pvp_join` честно (provably-fair) выбирает победителя, начисляет выплату и
  помечает раунд `done`. Атомарный переход `countdown → resolving` не даёт
  разыграть раунд дважды.
- **Cron-бэкстоп** (`api/cron`, раз в минуту) дорешает раунды, если все
  закрыли приложение и опрашивать состояние некому.
- Экономика с ботами честна и на общих раундах: матожидание выплат реальным
  игрокам = их суммарная ставка × (1 − rake), т.е. дом всегда в плюсе на rake.

Боты добавляются для «живости», но выплату получают только реальные
победители (у бота нет `tg_id`). Настоящие деньги (грн) в PVP не участвуют.

## Реферальная система

Реферер получает долю от **дохода платформы**, который принёс приглашённый
игрок, — не от его депозита. Источник выплаты только рейк: программа не может
уйти в минус независимо от того, как играет приглашённый.

Доход платформы по завершённой сессии:

| игра | доход |
|---|---|
| PVP | удержанный рейк (банк − выплата победителю), поделённый между участниками пропорционально ставкам |
| Crash | ставка − выплата (разбился или бросил → вся ставка; забрал по множителю > 1 → доход отрицательный) |
| Roulette | ставка − выплата по множителю приза |

Доход ноль или отрицательный — вознаграждение не начисляется.

Процент задаётся `referral_share_percent` в `shark_config` (по умолчанию 10) и
зажимается в 0..100 при чтении: опечатка в базе иначе платила бы больше, чем
платформа заработала.

Идемпотентность — ключом на игровую сессию (`ref_rev:pvp:<раунд>:<игрок>`,
`ref_rev:crash:<ставка>`, `ref_rev:roul:<ставка>`), поэтому повторный резолв
раунда, повторный кэшаут или проход cron не начисляют второй раз.

Сверх этого пригласившему идёт разовый бонус `referral_bonus_ton` — при первом
пополнении друга, а не за переход по ссылке: иначе регистрация одноразовых
аккаунтов сама по себе приносила бы деньги.

**Решение первой версии: начисление считается ПО СЕССИИ, сразу после её
завершения.** Это не то же самое, что доля от чистой прибыли за период: если
игрок поймал крупный выигрыш, итог платформы за отрезок времени может быть
отрицательным, притом что по отдельным проигранным им сессиям вознаграждение
начислено законно. Модель с перерасчётом по итогам периода потребовала бы
отложенных начислений и здесь сознательно не делается.

## Пополнение звёзд (Telegram Stars)

Игрок покупает игровые звёзды за Telegram Stars (валюта XTR):
- фронт запрашивает `create_stars_invoice` → сервер создаёт invoice-ссылку
  (`createInvoiceLink`, currency XTR) → открывается `TGAPP.openInvoice`;
- зачисление делает бот в `successful_payment` — идемпотентно по
  `telegram_payment_charge_id` (повторный вебхук не задваивает звёзды);
- пакеты и бонусы — на сервере (`STAR_PACKS`), клиенту не доверяем.

Требуется бот с включёнными платежами (Stars работают без provider_token).

## Пополнение звёзд (@CryptoBot, USDT)

Второй способ пополнения — оплата криптой через **@CryptoBot** (Crypto Pay).
Экран «Пополнить звёзды» показывает вкладки **🤖 Крипто Бот** / **⭐ Stars**.

- `create_cryptobot_invoice` создаёт счёт через `POST /createInvoice`
  (Crypto Pay API), клиент открывает `bot_invoice_url` в Telegram.
- Зачисление — **не через вебхук**, а ленивым опросом (как резолв PVP-раундов):
  клиент раз в 5 секунд дёргает `cryptobot_check`, который спрашивает статус
  инвойса у Crypto Pay напрямую **нашим секретным токеном** (`getInvoices`).
  Это безопаснее вебхука на serverless — не нужно проверять HMAC-подпись на
  «сыром» теле запроса (у обычных Vercel-функций это не тривиально), а сам
  запрос статуса аутентифицирован токеном, подделать нельзя.
- Идемпотентность — по `invoice_id` (уникальный `idem` в леджере): повторные
  опросы после первого зачисления просто возвращают текущее состояние.
- 10% с оплаты — пригласившему в ⭐ (без суточного лимита), как и у Stars.

### Настройка (@CryptoBot)
1. Открой **@CryptoBot** в Telegram → **Crypto Pay** → создай приложение
   (App) для приёма платежей.
2. Скопируй **API Token**.
3. Vercel → Environment Variables → добавь `SHARK_CRYPTOBOT_TOKEN`.
4. Redeploy.

Пакеты — `CRYPTOBOT_PACKS` в `api/shark.js` (цены в USDT, зачисление то же
количество звёзд, что и в Stars-пакетах).

## Локализация (укр / рус / англ)

Украинский — язык по умолчанию, с автоопределением по `language_code` из
Telegram (`ru`→рус, `en`→англ, иначе укр); ручной выбор в Настройках
запоминается в `localStorage`. Переведены все экраны: онбординг, Home,
таб-бар, Игры (краш/рулетка), PVP, Конкурсы/Лидеры/Магазин, Профиль,
Друзья, История, Достижения, Настройки — включая динамические тосты,
шторки (вывод/пополнение/покупка подарка) и записи в истории операций.

Словарь — объект `I18N` в `index.html` (`t(key)`/`tf(key, vars)`).
Для реальной серверной Истории (`api/shark.js` → `mapHistory`) сервер
отдаёт нейтральный `kind` + сырые числа — заголовок и валюта форматируются
на клиенте через `t()`, поэтому переводятся вместе с остальным интерфейсом.
Имена ботов, названия подарков и призов оставлены как есть (не текст
интерфейса).

## Аватарки ботов (реальные фото)

Боты в Рулетке, Краше, демо-PVP и Лидерах используют реальные фото
животных вместо эмодзи — `assets/avatars.png` (один спрайт-лист,
21 кадр в ряд). `AVATAR_SPRITE`/`avatarBgStyle()`/`avDiv()` в
`index.html` вычисляют `background-position`/`background-size` под
нужный размер аватарки (28px в списках, 44px в Краше, 38px в
Лидерах); если ключ не найден в спрайте (например `🙂` у «вас» самих),
`avDiv()` рисует как обычный эмодзи — так что новые сущности можно
добавлять без доп. кода. Список ключей — `BOT_AV`/`CRASH_AV`/`LEADERS`.

## Пока не заведено на сервер (v1)

Достижения, конкурсы и лидеры — пока витринные (в серверном режиме звёзды за
них не начисляются, чтобы не расходиться с балансом). Это следующий этап.

**Ещё способы пополнения (по образцу Epic Gift):**
- **TON-кошелёк** — не реализован: требует интеграции TON Connect на фронте
  и слежения за блокчейном на сервере (кто и сколько перевёл). Заметно
  больше работы, чем Крипто Бот; следующий кандидат после него.
- **Подарки (приём NFT-подарков как оплаты)** — сознательно пропущено:
  публичного API «оценить подарок и зачесть как оплату» у Telegram нет,
  похоже на нестандартное решение Epic Gift на грани возможностей платформы.
