# PRO Trainer — нативная оболочка

Веб-приложение из `trainer/` заворачивается в Capacitor: тот же `index.html`,
плюс мост к магазину для подписок. Отдельного кода приложения тут нет — только
обвязка.

> **Статус: строительные леса.** В этой среде нет доступа к npm, поэтому
> проект **не установлен и не собран** — команды ниже нужно выполнить у себя.
> Проверено здесь только то, что `sync:web` корректно собирает `www/` и
> подключает мост, и что приложение работает и с мостом, и без него
> (5 проверок в `trainer/tests/smoke.js`, раздел «доступ: міст до магазину»).

---

## Быстрый старт

```bash
cd trainer/native
npm install
npm run sync:web            # собирает www/ из trainer/ и вшивает iap-bridge.js
npx cap add ios             # нужен macOS + Xcode
npx cap add android         # нужен Android Studio
npm run ios                 # sync + открыть Xcode
npm run android             # sync + открыть Android Studio
```

`www/`, `ios/`, `android/` и `node_modules/` в git не попадают — они
генерируются командами выше (см. `.gitignore`).

После любой правки `trainer/index.html`:

```bash
npm run sync                # sync:web + npx cap sync
```

## Мост к магазину

`iap-bridge.js` кладёт в `window.ProTrainerIAP` объект, который приложение
уже умеет использовать:

| метод | что возвращает |
|---|---|
| `platform` | `'ios'` \| `'android'` |
| `buy(productId)` | `{ok, transactionId?, ts?, expiresAt?, error?}` |
| `restore()` | `{ok, purchases:[{productId, transactionId, ts, expiresAt?}]}` |
| `status()` | `{ok, active, productId?, expiresAt?, autoRenew?}` |

Если магазин сообщает `expiresAt` — приложение берёт его, а не считает дату
само: магазин знает про продления и отмены больше. `status()` вызывается при
запуске и возвращении на экран, поэтому отмена автопродления в настройках
iOS/Android подхватывается сама.

Без моста (обычный браузер, Vercel) приложение честно уходит в демо-режим и
пишет об этом на экране оплаты.

### Провайдер

В начале `iap-bridge.js` — `CONFIG.provider`:

- **`revenuecat`** (по умолчанию) — `@revenuecat/purchases-capacitor`.
  Даёт серверную проверку чеков и общие права доступа между устройствами,
  то есть закрывает дыру «переустановил приложение → получил новый пробный
  период». Бесплатно до определённого объёма выручки.
- **`cdvpurchase`** — `cordova-plugin-purchase` (CdvPurchase v13), если
  внешний сервис не нужен. Тогда проверку чеков придётся делать самим.

Подставьте ключи в `CONFIG` и **сверьте названия методов с версией плагина**,
которую поставите: API между мажорными версиями меняется.

## App Store Connect

1. Приложение с bundle ID `com.protrainer.app` (или своим — тогда поправьте
   `capacitor.config.json`).
2. **Subscriptions → Subscription Group** «PRO Trainer», в ней три
   auto-renewable подписки. Сейчас этот шаг не нужен: сборка идёт с
   `PRO_TRAINER_FREE`, внутри ничего не продаётся, и человек платит на сайте
   гривной (299 / 749 / 1990 ₴). Таблица ниже — на день, когда встроенные
   покупки включат:

   | Product ID | Длительность | Цена |
   |---|---|---|
   | `pro_trainer_monthly` | 1 месяц | $4.99 |
   | `pro_trainer_quarterly` | 3 месяца | $12.99 |
   | `pro_trainer_yearly` | 1 год | $49.99 |

3. Локализации названий и описаний, скриншот экрана оплаты для ревью.
4. **Paid Apps Agreement** подписан, банковские и налоговые данные заполнены —
   без этого покупки не работают даже в sandbox.
5. Sandbox-тестировщики (Users and Access → Sandbox Testers).
6. App-Specific Shared Secret — в RevenueCat (или в свой сервер валидации).
7. App Store Server Notifications V2 → URL RevenueCat (или свой).
8. В App Privacy указать, что данные клиентов хранятся на устройстве и не
   собираются разработчиком.
9. Ссылки на **Условия** и **Политику** — они уже есть в приложении
   (экран оплаты → внизу), но Apple требует ещё и URL в метаданных.

## Google Play Console

1. Приложение с тем же `applicationId`.
2. **Monetize → Subscriptions**: три подписки с теми же ID и base plans
   `P1M`, `P3M`, `P1Y`, цены $4.99 / $12.99 / $49.99. Как и в App Store
   Connect — только когда встроенные покупки включат; сейчас продаёт сайт.
3. Загрузить сборку хотя бы в internal testing — без этого подписки не
   активируются.
4. **License testers** (Play Console → Setup → License testing).
5. Real-time developer notifications (Pub/Sub topic) → RevenueCat или свой
   сервер.
6. Data safety: данные клиентов хранятся на устройстве, не передаются.

## Что приложение делает само, когда плагины на месте

Кода писать не нужно — приложение проверяет `window.Capacitor.Plugins` и
переключается само. Достаточно `npm install`.

- **`@capacitor/preferences` — надёжное хранилище.** `localStorage` в WebView
  система может очистить при нехватке места. Приложение пишет и туда, и в
  нативное хранилище, а при старте поднимает данные оттуда (нативное
  главнее) и возвращает копию в WebView. Без плагина работает как раньше —
  только `localStorage`.
- **`@capacitor/local-notifications` — напоминания при закрытом приложении.**
  Приложение планирует уведомления заранее по выбранным интервалам
  (1 час / 30 / 15 / 5 минут), пересобирает расписание при каждом изменении
  тренировок и снимает отменённые. Пока плагина нет — напоминания приходят
  только с открытым приложением.

  iOS держит не больше 64 запланированных уведомлений на приложение, поэтому
  расписание расходует слоты осознанно: сначала по одному на каждое
  тренирование, и лишь потом второй интервал ближайшим. Покрытие видно в
  настройках («Заплановано до …»), а когда слотов не хватает, последним
  ставится напоминание открыть приложение.

  На Android 13+ разрешение `POST_NOTIFICATIONS` запрашивает сам плагин при
  первом обращении — в приложении это кнопка «Дозволити сповіщення» в
  настройках. Иконку статус-бара положите как `ic_stat_icon`
  (`android/app/src/main/res/drawable/`), цвет уже задан в
  `capacitor.config.json`.

## Что стоит добавить дальше

- **Автобэкап в облако** (iCloud / Google Drive) вместо файла.
- **Фоновое перепланирование** (`@capacitor/background-task`): сейчас расписание
  пересобирается, когда приложение открыто, и тянется на 5–17 дней в
  зависимости от загруженности. Фоновая задача убрала бы и этот предел, но на
  iOS она выполняется когда система сочтёт нужным, так что заменить ею
  напоминание «відкрийте застосунок» нельзя — только дополнить.

## Проверка перед сдачей в ревью

1. Пробный период: новый аккаунт → 14 дней, полный доступ.
2. Покупка каждого из трёх планов в sandbox → доступ, дата окончания из
   магазина.
3. Отмена автопродления в настройках ОС → приложение показывает
   «Автопродовження вимкнено», доступ до даты.
4. «Відновити покупку» после переустановки → доступ возвращается.
5. Отказ оплаты и отмена окна оплаты → данные целы, приложение предлагает
   повтор.
6. Авиарежим → приложение работает, статус синхронизируется после сети.

## Почему contentInset: never

iOS умеет сам отодвигать веб-страницу от «чёлки» и от полосы home —
`contentInset: "always"`. Наше приложение делает это само: у него
`viewport-fit=cover`, а отступы посчитаны через `env(safe-area-inset-*)`
на каждом экране, включая онбординг и нижнюю панель.

Когда отступ ставится дважды, страница не достаёт до низа экрана, и в
освободившейся полосе видно фон нативной оболочки. Он тёмный — и на
светлой теме это чёрная полоса поперёк экрана. Так и выглядела первая
сборка на настоящем телефоне.

Поэтому оболочка отступов не делает: страница занимает экран целиком, а
безопасные зоны остаются заботой CSS — там, где их и так считают.
