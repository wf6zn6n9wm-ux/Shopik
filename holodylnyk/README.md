# Холодильник+

Застосунок обліку продуктів. Фотографуєш чек після магазину — позиції,
терміни придатності, гроші та ритм покупок рахуються самі.

```
app/          застосунок · один файл, без збірки й залежностей
scanner/      ендпоінт розпізнавання чека · Node, окремий деплой
design/       дизайн-система · токени двох тем, іконки, генератори
prototypes/   макети, які не пішли в основну гілку
test/         прогін інтерфейсу в headless-браузері
```

## Зібрати й відкрити

```bash
python3 app/build.py      # вшиває шрифти → app/index.html
```

`app/index.html` самодостатній: відкривається файлом, працює офлайн,
нічого не завантажує ззовні. Його ж і деплоїмо.

## Тести

```bash
sh test/run.sh            # 111 перевірок інтерфейсу, ключ і мережа не потрібні
cd scanner && node test/run.js   # 88 перевірок розбору чека й ціни
```

`test/app.js` проходить застосунок як людина: онбординг, пошук, фільтри,
списання, чек, голос, штрихкод, ручний ввід, заморозка, частки, категорії,
історія, КБЖУ, гроші, ритм, теми. `test/scanner-live.js` — наскрізний прогін
живого сканера з підміненим `fetch`.

## Головна ідея

Розпізнавання тексту — **не** вузьке місце. Сучасна vision-модель читає
зім'ятий чек, знятий під кутом. Вузьке місце — те, що відбувається після:

| Задача | Vision | Реєстр ДПС | Словник |
|---|:--:|:--:|:--:|
| Прочитати текст | ✅ | ✅ | — |
| `МЛК ЯГОТ 2,5%` → «Молоко» | ❌ | ❌ | ✅ |
| Відсіяти «Точилка-гумка» | ❌ | ❌ | ✅ |
| Проставити термін придатності | ❌ | ❌ | ✅ |

Тому словник детермінований і покритий тестами, а модель — запасний варіант,
і кожна позиція від неї позначена `needs_review`.

Друга опора — **перевірка цілісності чека**. Обидва контрольні числа
надруковані на самому папері: сума позицій проти підсумку і ПДВ проти ставки.
Якщо не сходиться — застосунок каже, що чек неповний, а не мовчки кладе
в холодильник половину.

## Скільки коштує одне фото

Кожне фото чека — це платний виклик моделі, і платить власник застосунку.
Тому сканер читає чек **сходинками**:

```
фото → дешева модель → чек зійшовся сам із собою?
                        ├── так      готово, заплатили копійки
                        ├── partial  перечитати дорогою моделлю
                        └── reshoot  папір обрізаний — просити перезняти
```

Ключове тут те, що рішення приймається **не на довірі до моделі, а по
самому чеку**: сума позицій проти надрукованого підсумку. Дорога модель
вмикається лише там, де дешева довела свою помилку. На `reshoot` ескалації
немає навмисно — обрізане фото друга модель прочитає так само.

Ціну видно з кожного прогону: API повертає `usage` по кожній спробі,
`lib/cost.js` перераховує в гроші, `tools/batch.js` пише в звіт частку
ескалацій. Прикидки в README немає навмисно — має бути виміряна цифра
з ваших чеків.

| Змінна | За замовчуванням | Що робить |
|---|---|---|
| `AI_MODEL` | `claude-haiku-4-5` | перша, дешева сходинка |
| `AI_MODEL_FALLBACK` | `claude-opus-5` | друга сходинка; порожнє значення вимикає її |
| `AI_EFFORT` | `medium` | `low`, `high` — глибина мислення там, де воно є |

Головне, що варто знати заздалегідь: **вихідні токени дорожчі за вхідні
вп'ятеро, і «мислення» рахується як вихід**. Звідси все інше — і чому
Haiku 4.5 дешевший не в п'ять разів, а більше (він не думає, якщо не
попросити), і чому `AI_EFFORT` важливіший за стиснення фото. Фото чека
стискати якраз шкідливо: дрібний друк і так на межі читабельності.

Щоб порівняти точність із ціною, женіть ту саму пачку в трьох режимах:

```bash
node tools/batch.js ./photos                             # сходинками
AI_MODEL_FALLBACK= node tools/batch.js ./photos          # тільки дешева
AI_MODEL=claude-opus-5 AI_MODEL_FALLBACK= node tools/batch.js ./photos
```

Ціни в `lib/cost.js` — станом на 2026-06-24, звіряйтеся з прайсом.
Курс гривні приблизний: `UAH_PER_USD=41.5 node tools/batch.js …`.

### Шляхи, де модель не потрібна взагалі

Обидва вимагають перевірки на реальних чеках, обидва здатні прибрати
більшу частину витрат — і обох у коді ще немає:

- **QR-код на чеку.** Кожен фіскальний чек в Україні має QR, а ДПС тримає
  відкритий сервіс пошуку чека — без авторизації, цілодобово. Якщо він
  віддає позиції, а не лише факт реєстрації, то для свіжих чеків модель
  не потрібна зовсім. Перевіряється за п'ять хвилин із будь-яким чеком
  у руках: `cabinet.tax.gov.ua/cashregs/check`.
- **OCR на самому телефоні.** Apple Vision розпізнає українську (`uk-UA`)
  локально, безкоштовно й офлайн. Розбір рядків, словник і перевірка суми
  в цьому проєкті вже детерміновані — тобто модель потрібна лише там, де
  OCR не впорався, і це видно з тієї ж перевірки суми.

## Дизайн-система

Один інтерфейс, дві теми: blush pink і deep navy з бірюзою. Структура,
розміри, іконки й відступи однакові — змінюється лише набір кольорів.

`design/tokens.json` — джерело правди. З нього генеруються `tokens.css`
і `Tokens.swift`, тому три файли не можуть розійтися:

```bash
cd design && python3 gen_tokens.py    # json → css + swift
cd design && python3 gen_system.py    # → system.html, сторінка документації
```

Тема стоїть на `<html data-t="light|dark">`. Значення `system`
розвʼязується в коді — у розмітці третього стану не існує.

## Стан роботи

Зроблено: сканер чека з перевіркою цілісності, терміни за категорією,
заморозка, часткове списання, категорії, історія чеків, камера, живий
сканер, КБЖУ, обмін даними файлом, гроші (вартість холодильника, особиста
інфляція, порівняння магазинів), ритм покупок, дизайн-система у двох темах.

Не зроблено, і це треба знати:

- **Ендпоінт жодного разу не працював проти живого API.** Усі тести гоняють
  записаний витяг із двох справжніх чеків. Поки не прогнали 20–30 реальних
  чеків із різних мереж, цифра точності нічим не підтверджена.
- **Голос і штрихкод — витрина.** Екрани є, справжніх `SpeechRecognition`
  і `BarcodeDetector` немає.
- **Синхронізація сімʼї — обмін файлом.** Справжня потребує сервера.
- **Це ще не застосунок, а сторінка.** Немає PWA-маніфесту, service worker
  і push — отже нагадування фізично не дійде.
