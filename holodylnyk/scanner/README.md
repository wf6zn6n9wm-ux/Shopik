# Холодильник+ · сканер чеків

Фото українського касового чека → позиції з нормалізованими назвами,
категоріями, термінами придатності та **чесним вердиктом, чи зійшовся чек**.

```
POST /api/receipt
{ "image": "data:image/jpeg;base64,..." }
```

## Головна ідея

Розпізнавання тексту — **не** вузьке місце. Сучасна vision-модель читає
зім'ятий чек, знятий під кутом. Вузьке місце — те, що відбувається після:

| Задача | Vision | Реєстр ДПС | Словник |
|---|:--:|:--:|:--:|
| Прочитати текст | ✅ | ✅ | — |
| `МЛК ЯГОТ 2,5%` → «Молоко» | ❌ | ❌ | ✅ |
| Відсіяти «Точилка-гумка» | ❌ | ❌ | ✅ |
| Проставити термін придатності | ❌ | ❌ | ✅ |

Реєстр ДПС віддав би **ті самі скорочення**, що надруковані на папері, — і
для апаратних РРО лише наступного робочого дня. Тому канал не має значення,
а має значення словник. Він тут детермінований і тестований.

## Архітектура

```
фото
 └─▶ vision (claude-opus-5, structured output)   lib/schema.js
      сирі рядки як надруковано + числа + якість кадру
       └─▶ нормалізація                          lib/normalize.js
            словник → категорія                  lib/dictionary.js
            модель → фолбек, позначений needs_review
             └─▶ терміни за категорією           lib/shelflife.js
                  └─▶ перевірка цілісності       lib/validate.js
```

**Словник перший, модель запасна.** Там, де словник знає перше слово,
думка моделі не питається. Українські мережі ставлять категорію першим
словом — «Батончик 90 г Nestle Lion King», «Вода 1,5 л Buvette» — тому
нормалізація будується навколо першого токена.

## Перевірка цілісності

Найважливіша частина. Обидва контрольні числа надруковані **на самому чеку** —
жодних зовнішніх джерел, перевірка безкоштовна.

1. **Сума позицій проти підсумку.** Розійшлися — частина стрічки не в кадрі.
2. **ПДВ проти ставки.** Якщо весь чек за 20%, то ПДВ = сума / 6.
   Не сходиться — у чеку є позиції за іншою ставкою, отже він неповний.

Вердикт: `ok` · `partial` · `reshoot`.

## Тести

```bash
npm test    # ключ і мережа не потрібні
```

Фікстури — записаний витяг із **двох справжніх чеків**, включно з поганим:
зім'ятим, знятим під кутом, обрізаним зверху.

```
Чек 1 · АТБ, 24.08.2025      сума зійшлася 77,40 = 77,40
Чек 2 · обрізаний, 11.01.2022 не вистачає 239,60 ₴ → reshoot
                              ПДВ 44,88 ≠ 51,58 → інші ставки вище

Позицій оброблено: 7
Категорію дав словник: 6/7 (86%)
```

Сьома позиція — «Ролліні 95 г з телятиною». Словник її не знає, категорію
дала модель, позиція позначена `needs_review`. Саме такі рядки — кандидати
в словник.

## Прогін справжніх чеків

Це та перевірка, без якої цифра точності нічого не означає. Розгорнутий
ендпоінт для неї **не потрібен** — лише ключ і Node.

```bash
npm install
mkdir photos                      # складіть туди 20-30 фото чеків, jpeg
ANTHROPIC_API_KEY=sk-ant-… node tools/batch.js ./photos
```

На виході — `photos/report.md`:

- **скільки чеків зійшлося за сумою.** Сума позицій дорівнює надрукованому
  підсумку — найсильніший доказ, що числа прочитані вірно, і він
  безкоштовний, бо обидва числа надруковані на самому папері;
- **яку частку категорій дав словник**, а не модель;
- **таблиця слів, яких у словнику немає**, за частотою — це готовий список
  того, що додавати в `lib/dictionary.js`;
- **назви позицій по кожному чеку** — для звірки очима з фото.

Чого прогін не вміє: перевірити, чи правильно прочитані **назви**. Це
можливо тільки очима, тому останній розділ звіту існує саме для цього.
Перевірте так три-чотири чеки — цього достатньо, щоб зрозуміти картину.

HEIC із айфона модель не приймає: у налаштуваннях камери поставте
«Найсумісніший» або переведіть фото в jpeg.

## Що далі

- **Словник росте з реальних чеків.** Кожна позиція з `category_source:
  "unknown"` — рядок, який треба додати. Логуйте їх.
- **Штрихкоди.** `barcode_resolvable` показує, чи є сенс питати зовнішню базу.
  Коди, що починаються з `2`, — внутрішні для мережі й не резолвляться ніде
  (перевірено на чеку АТБ: `2999300069184` внутрішній, `7613036731713` — Nestlé).
- **Довгий чек.** На 30 позицій стрічка не влізе в кадр — потрібне склеювання
  кількох фото. Перевірка суми вже вміє це ловити.
