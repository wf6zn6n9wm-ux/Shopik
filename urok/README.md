# Urok+

CRM для репетиторів, викладачів і тренерів. Одна система, у якій
пов'язані всі сутності роботи:

```
учень → розклад → заняття → домашнє завдання → оплата → дохід → статистика
```

Учень знає про свої заняття, заняття — про гроші й домашку, гроші —
про статистику. Тому картка учня відповідає на все одразу: коли
наступне заняття, чи є борг, що задано, скільки проведено й зароблено.

Застосунок самостійний і не пов'язаний з рештою репозиторію: власна
дизайн-система, власні дані, власні тести. Відкривається за адресою
`/urok/`.

```
urok/
  index.html                оболонка + дизайн-система (весь CSS тут)
  src/                      застосунок, дванадцять модулів у порядку завантаження
  tests/                    перевірки (пісочниця + сценарій у браузері)
  tools/preview.js          статичний рендер екранів для перевірки дизайну
  tools/bundle.js           однофайлова збірка без мережі
  tools/runtime.js          мінімальний React для тієї збірки
  sw.js, manifest, icon     PWA-обгортка
```

## Запуск

Потрібен звичайний HTTP-сервер — з `file://` браузер не дасть завантажити
модулі:

```sh
cd urok && python3 -m http.server 8080   # → http://localhost:8080
```

Збірки немає. React і Babel беруться з CDN, JSX компілюється в браузері —
як і в решті застосунків цього репозиторію. Ціна — кілька сотень
мілісекунд на старті; виграш — жодного `node_modules` і правка коду без
пересборки.

## Перевірки

```sh
node urok/tests/i18n.js     # три мови, множина, підстановки
node urok/tests/smoke.js    # екрани в трьох мовах, гроші, домашка, статистика
node urok/tests/browser.js  # живий сценарій у справжньому браузері
```

`tests/harness.js` склеює `src/*.js` у тому ж порядку, що й `index.html`,
транспілює JSX (bun або `@babel/standalone`) і виконує з заглушками
React, `localStorage` і `document`. Кожен екран реально викликається —
ловляться забуті змінні, биті екрани, неперекладені рядки, класи без
стилів і розбіжність `sw.js` зі списком модулів.

Пісочниця не бачить DOM, подій і фокуса, тому є ще `browser.js`: він
збирає автономний файл і проходить ним живий сценарій у headless
Chromium — вхід, онбординг, вкладки, картка заняття й учня, фінанси,
зміна теми й мови, пошук, створення заняття. Саме він знайшов, що в
автономному рантаймі `onChange` слухав `change` замість `input`, і
поля мовчали під час набору. Якщо браузера немає, тест каже про це й
виходить із нулем.

Усі три перевірки ганяються в CI на кожну зміну в `urok/`
(`.github/workflows/urok.yml`).

## Прев'ю дизайну

```sh
node urok/tools/preview.js uk > /tmp/preview.html          # усі екрани
node urok/tools/preview.js en market,premium > /tmp/p.html # вибірково
```

Ті самі компоненти рендеряться в статичний HTML і вставляються в рамки
телефонів — світлу й темну — з тим самим CSS, що й у застосунку. Зручно
дивитися дизайн одним поглядом і знімати скриншоти для сторів. У
застосунок цей файл не входить.

## Автономна збірка

```sh
node urok/tools/bundle.js > /tmp/urok.html            # цілий документ
node urok/tools/bundle.js --fragment > /tmp/urok.html # без <html>/<body>
node urok/tools/bundle.js --no-demo                   # без демо-даних
```

Один файл без жодного зовнішнього запиту: CSS із `index.html`, JSX
транспільований заздалегідь, а замість React — `tools/runtime.js`
(createElement, ключі, фрагменти, useState/useEffect/useMemo/useRef,
createRoot). Оновлення там — повний перерендер кореня з порівнянням
дерева; DOM-вузли не пересоздаються, тому фокус у полях лишається.

Потрібно це там, де сторінка не може ходити в CDN: артефакт, прев'ю,
офлайн-демо, скриншоти. У самому застосунку працює справжній React —
рантайм у `index.html` не підключений і в `sw.js` не кешується.

Автономна збірка сама наливає демо-дані на першому запуску (той самий
перемикач, що в налаштуваннях), інакше знайомство починалося б із
порожнього тижня.

## Архітектура

**Модулі.** Кожен файл у `src/` — окрема область видимості (IIFE), яка
бере залежності з `window.U` і кладе туди своє. Порядок підключення
задає `index.html`; тест падає, якщо файл додали в одне місце й забули в
іншому. Окремі `<script>` ділять глобальний лексичний простір, тому
однакове ім'я в двох файлах — це `SyntaxError` ще до першого кадру; IIFE
знімає це питання.

| файл | що всередині |
| --- | --- |
| `00-i18n.js` | словники uk/ru/en, множина, назви днів і місяців |
| `10-core.js` | моделі, стан, дати, гроші, ліміти, міст до покупок |
| `20-ui.js` | іконки й примітиви (картки, рядки, поля, шторки, тости) |
| `30-auth.js` | вітання, вхід за номером, код, ім'я, онбординг |
| `40-calendar.js` | головний екран: сьогодні, тиждень, гроші, домашка |
| `45-lesson.js` | створення заняття, повтори, картка заняття |
| `48-homework.js` | домашні завдання: список, картка, форма |
| `50-students.js` | список, форма, картка учня, оплати |
| `55-finance.js` | фінанси: періоди, графік, борги, статистика |
| `60-market.js` | каталог матеріалів і сторінка матеріалу |
| `70-profile.js` | профіль, налаштування, підписка, змагання, довідка |
| `90-app.js` | навігація, вкладки, стек, корінь |

**Стан.** Один об'єкт, який цілком пишеться в `localStorage` під ключем
`urok.v1` і роздається через підписку (`store` + хук `useStore`). Дії
зібрані в `A` — кожна є чистою функцією над станом, тому їх видно з
тестів без React. Збережений стан завжди зливається з типовим
(`merge`), тому нові поля після оновлення не зникають, а старі дані не
ламають застосунок.

**Дані.** Усе плоске, зв'язки по `id` — так само ляже в SQL, коли
з'явиться сервер:

```
profile   {name, photo, color, phone, email, subjects[], bio}
student   {id, name, subject, color, photo, phone, email, birthday, notes, price, archived, createdAt}
lesson    {id, studentIds[], subject, date, start, end, price, prices{}, status, note, seriesId}
series    {id, freq, days[], start, end, price, studentIds[], from, until}
homework  {id, studentIds[], lessonId, title, description, issuedAt, dueDate, status, checked}
payment   {id, studentId, amount, date, method, type, lessonId}
```

Статуси заняття: `planned → done | canceled | missed`. «Скасовано» і
«не відбулося» — різні речі: перше зняли завчасно, друге коштувало
викладачеві часу, і в статистиці вони стоять окремо. Домашнє завдання
йде `todo → doing → done`, а далі викладач ставить `checked` — саме це
дає число «потребують перевірки» на головному екрані.

Ціна живе на занятті (`price`), а `prices` перекриває її для окремих
учнів — у групі однакова ціна радше виняток.

Дати скрізь — рядки `YYYY-MM-DD`, час — `HH:MM`. Рядок як ключ не має
часових поясів і не з'їде на добу при серіалізації.

Повторювані заняття не «віртуальні»: правило серії одразу розкладається
в конкретні заняття на 12 тижнів наперед (`expandSeries`), тому будь-яке
з них можна перенести чи скасувати поштучно. Видалення серії не чіпає
минулого — історія має лишатись правдивою.

**Гроші.** Два різні числа, які легко переплутати й дорого плутати:
**дохід** — це проведені заняття (скільки заробив), **отримано** — це
оплати (скільки насправді в кишені). Різниця між ними і є борг або
передоплата, тому окремого поля «оплачено» на занятті немає — воно
завжди розходилося б із реальністю.

Замість нього — книга учня (`sel.ledger`): оплати закривають проведені
заняття за порядком у часі, адресні платежі — своє заняття. Плюс на
балансі означає «оплачено наперед», мінус — «мені повинні». Передоплата
працює сама собою: щойно заняття проведено, воно з'їдає гроші з
балансу. Заплановані заняття не рахуються ніде, крім рядка
«очікується».

**Навігація.** Чотири вкладки плюс стек екранів поверх них
(`nav.push / back / replace / go`). Стек живе в стані, а не в URL —
застосунок мобільний; системна кнопка «назад» під'єднана через
`history`, тому жест назад у браузері й на Android працює очікувано.

**Теми.** `data-theme` на `<html>`, усі кольори — змінні CSS. Тема
застосовується ще до першого кадру інлайн-скриптом, тому темна не
блимає білим на старті. Dark — не інверсія: власні значення фону,
поверхонь і ліній, спільний акцент. Значення `system` слухає
`prefers-color-scheme` наживо.

**Мови.** uk типова завжди, не «як у браузера» — так домовлено з
першого дня, а перемикач поруч у налаштуваннях. Ще є ru та en. У коді немає
жодного зашитого рядка інтерфейсу: усе через `t('ключ')`. Множина —
окремим механізмом (`t.plural`), бо в uk/ru три форми, а в en дві. Немає
перекладу — падаємо на uk, а не на порожнечу.

## Підписка

`Billing` у `10-core.js` — єдиний фасад для App Store, Google Play і
вебу. Зараз працює демо-провайдер: пробний тиждень і плани зберігаються
локально, щоб можна було пройти весь сценарій. Щойно в збірці з'явиться
нативний міст `window.UrokIAP` (`purchase`, `restore`), фасад підхопить
його автоматично — екрани підписки міняти не доведеться.

Ліміт безкоштовного плану (`FREE_STUDENT_LIMIT`, 5 активних учнів) —
м'який: він показує пропозицію в списку учнів і на екрані Premium, але
нічого не забирає. Заблокована робота означає, що викладач веде учнів
деінде — і тоді Urok+ уже не потрібен. Місце, де вмикається жорсткий
ліміт, одне: `sel.canAddStudent` і `sel.overFreeLimit`.

Так само зроблено вхід: `window.UrokAuth.apple()` перехоплює Apple Sign
In, якщо міст є; у вебі проходимо демо-кроками з тим самим порядком
екранів.

## Головний екран

Порядок блоків = порядок питань викладача зранку: який сьогодні день →
що на тижні → хто прийде → скільки заробив → що з домашкою → як іде
місяць. Блоки нижче першого екрана з'являються, лише коли їм є що
сказати: порожній розділ «Домашні завдання» — це шум, а не інформація.

Сповіщення не окремий канал, а те саме, що вже є в даних, показане як
короткі події: найближче заняття (з хвилинами, якщо воно от-от),
прострочені дедлайни, робота на перевірку, борги, дні народження.
Кожен рядок веде туди, де з подією можна щось зробити. Що саме
показувати — вирішують перемикачі в налаштуваннях.

## Що далі

Архітектура розрахована на те, щоб додати без переписування:
онлайн-запис учнів, справжні оплати, кабінет учня (домашні завдання
вже мають статуси під це), push-сповіщення, маркетплейс із продажем
власних матеріалів, рейтинги й інтеграції. Найближчі кроки — сервер
(той самий формат даних), StoreKit і push.
