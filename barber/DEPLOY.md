# Про Барбер — запуск

По шагам, от пустого места до первой принятой оплаты. Каждый шаг заканчивается
проверкой: если она не прошла, дальше идти незачем.

Оплату и онлайн-запись можно включать по отдельности — они не связаны. Кабинет
работает и без обеих.

---

## 1. Vercel

Приложение — статический `index.html` без сборки плюс функции в `api/`. Собирать
нечего, но **корень проекта должен быть `barber/`**, иначе `/api/licence` не
найдётся и оплата не заработает.

1. Vercel → Add New → Project → импортировать этот репозиторий.
2. **Root Directory: `barber`** ← самое важное.
3. Framework Preset: Other. Build Command и Output Directory оставить пустыми.
4. Deploy.

`package.json` в папке уже есть — Vercel сам поставит `@vercel/kv`.

**Проверка:** откройте `https://<домен>/api/health`. Должен ответить JSON.
Если 404 — Root Directory указан неверно.

---

## 2. Хранилище лицензий

Без него лицензии живут в памяти функции и исчезают между вызовами: барбер
платит, деньги уходят, доступ не появляется. Заметить это по приложению
невозможно — оно ведёт себя так, будто оплаты не было.

1. Vercel → Storage → Create → **Upstash for Redis** (в панели может называться
   KV) → подключить к проекту.
2. Переменные `KV_REST_API_URL` и `KV_REST_API_TOKEN` Vercel добавит сам.
   Если ваш проект назвал их иначе — код читает и `UPSTASH_REDIS_REST_*`, и
   `STORAGE_REST_API_*`, и те же имена с префиксом `BARBER_`.

**Проверка:** `/api/health` → `"storage":"kv"`. Если `"memory"` — хранилище не
подключилось, и продавать нельзя.

## 3. LiqPay

Нужен аккаунт мерчанта на приват24 для бизнеса. Оплата разовая, регулярных
списаний нет — подключать «регулярные платежи» не требуется.

1. LiqPay → Настройки → API → скопировать **public_key** и **private_key**.
2. Vercel → Settings → Environment Variables:

| Переменная | Значение |
|---|---|
| `BARBER_LIQPAY_PUBLIC_KEY` | публичный ключ |
| `BARBER_LIQPAY_PRIVATE_KEY` | приватный ключ — **секрет**, в браузер не попадает |
| `BARBER_PUBLIC_BASE_URL` | `https://<ваш домен>` без слэша в конце |

3. Redeploy (переменные подхватываются только при новой сборке).

`BARBER_PUBLIC_BASE_URL` — адрес, куда LiqPay пришлёт ответ об оплате.
Ошибётесь доменом — деньги спишутся, а доступ не появится, и по приложению это
будет выглядеть как «оплата не прошла».

**Проверка:** `/api/health` → `"liqpay":true`, `"baseMatchesHost":true` и
`"readyToSell":true`. Последнее означает: ключи есть, хранилище настоящее,
домен верный.

### Пробный платёж

1. Откройте кабинет, дойдите до экрана оплаты, укажите логин.
2. Заплатите 299 ₴ настоящей картой — тестового режима у LiqPay для этой схемы
   нет.
3. Кабинет должен сам увидеть оплату в течение нескольких секунд. Если нет —
   «Я уже оплатил».
4. `https://<домен>/api/licence?login=<ваш логин>&device=x` → `"needsClaim":true`
   (устройство другое) и настоящая дата в `expiresAt`.
5. Вернуть себе деньги: LiqPay → Платежи → возврат. Доступ снимется сам —
   `callback` со статусом `reversed` обнуляет срок.

## 4. Документы

LiqPay при проверке мерчанта смотрит, что документы открываются по указанным
адресам, а реквизиты в них — настоящие.

1. В `index.html` заполните `LEGAL.site` — адрес, где выложен кабинет.
2. `node barber/legal/sync.js export` — страницы пересоберутся.
3. Проверьте `/terms`, `/privacy`, `/support`, `/delete`.

Тексты вычитаны не юристом. Перед приёмом денег отдайте `legal/terms.md` и
`legal/privacy.md` на проверку, правки верните командой `import`.

## 5. Онлайн-запись (необязательно)

Кабинет работает без неё. Нужна, только чтобы клиенты записывались сами.

1. Supabase → SQL Editor → выполнить `schema.sql`.
2. Переменные окружения:

| Переменная | Зачем |
|---|---|
| `BARBER_SUPABASE_URL` | адрес проекта Supabase |
| `BARBER_SUPABASE_SERVICE_ROLE_KEY` | сервисный ключ — **секрет** |
| `BARBER_BOT_TOKEN` | токен Telegram-бота |
| `BARBER_BOT_USERNAME` | имя бота для ссылки привязки |
| `BARBER_TG_SECRET` | секрет вебхука Telegram |
| `BARBER_CRON_SECRET` | защита `/api/cron` от посторонних запусков |
| `BARBER_APP_URL` | адрес кабинета для ссылок в сообщениях |

3. Один раз поставить вебхук:

```
https://api.telegram.org/bot<TOKEN>/setWebhook?url=<APP>/api/bot&secret_token=<TG_SECRET>
```

**Проверка:** `/api/health` → `"booking":{"supabase":true,"bot":true,…}`. Дальше
в кабинете: Настройки → Онлайн-запись → включить, «Подключить Telegram».

Cron на вечернее сообщение уже прописан в `vercel.json` — `0 16 * * *`, это
19:00 по Киеву.

## Если что-то не так

| Симптом | Причина |
|---|---|
| `/api/health` → 404 | Root Directory не `barber` |
| `"storage":"memory"` | хранилище не подключено — лицензии исчезнут |
| `"liqpay":false` | ключи мерчанта не заданы или не сделан redeploy |
| `"baseMatchesHost":false` | `BARBER_PUBLIC_BASE_URL` указывает не на этот домен |
| Оплата прошла, доступа нет | смотрите LiqPay → Платежи → callback: ответ должен быть 200 |
| В кабинете «оплата не подключена» | приложение не нашло `/api/licence` — Root Directory или домен |
| Заявки не приходят | `booking.supabase` в health, затем вебхук бота |

Все проверки перед деплоем: `node barber/tests/smoke.js`, `api.js`, `licence.js`.
Они не заменяют пробный платёж — настоящий LiqPay ими не проверить.
