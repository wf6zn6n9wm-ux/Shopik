# PRO MASSAGE — кабинет массажиста

**Открыл между двумя клиентами — за две секунды понял, что делать дальше.**

Рабочее пространство частного массажиста: расписание, клиенты, история сеансов,
карта тела, заметки после сеанса, абонементы, доход, аналитика и онлайн-запись.
Не витрина и не макет: каждая кнопка что-то делает, деньги пересчитываются из
проведённых сеансов, изменения переживают перезагрузку.

Открывается по прямой ссылке `/massage/`. Самодостаточный `index.html`
(React 18 UMD + Babel standalone, инлайновые SVG-иконки, без сборки) — как
соседние приложения репозитория. Данные лежат в `localStorage`, сервер не нужен.

| Файл | Что это |
|---|---|
| `index.html` | весь кабинет: экраны, состояние, дизайн-система |
| `tests/smoke.js` | проверки без браузера: расчёты, действия, все экраны |
| `icon.svg`, `manifest.webmanifest` | иконка и PWA-манифест |

## Экраны

| Экран | Одна задача экрана |
|---|---|
| **Главная** | что происходит сегодня: ближайший сеанс, день, что требует внимания |
| **Расписание** | когда сеансы: полоса недели, лента дня, свайп между днями |
| **Клиенты** | кто мои клиенты: поиск, недавние / по алфавиту / частые |
| **Профиль клиента** | что я знаю об этом человеке: обзор, история, заметки, прогресс |
| **Карта тела** | где напряжение и как оно меняется: 9 зон, 4 уровня, комментарий к зоне |
| **Сеанс** | что происходит прямо сейчас: таймер, зоны, диктовка, завершение |
| **Доход** | сколько заработал: день, неделя, месяц, год |
| **Аналитика** | как работает бизнес: загрузка, услуги, клиенты, часы пик |
| **Абонементы** | кто оплатил вперёд и что уже списано |
| **Онлайн-запись** | как клиент записывается: услуга → дата → время |
| **Уведомления** | что требует внимания: «Сегодня» и «Ранее», прочитано / нет |
| **Настройки** | профиль, услуги, рабочий день, тема, данные |

Навигация — нижняя, пять мест: **Главная · Клиенты · + · Расписание · Ещё**.
Центральная «+» открывает четыре начала: новая запись, новый клиент, новый
сеанс, добавить оплату.

## Дизайн-система

Светлая тема — основная. Тёмная — не инверсия, а свой набор значений тех же
токенов: фиолетовый графит, карточки светлее фона, приглушённая пастель.

| Токен | Light | Dark | Роль |
|---|---|---|---|
| `--violet` / `--violet-2` | `#5B3FD3` / `#7448E8` | `#8465F0` / `#9B7CFF` | акцент и градиент |
| `--bg` | `#FAFAFC` | `#0F0E15` | фон |
| `--card` / `--card-2` | `#FFFFFF` / `#F7F7FA` | `#1A1924` / `#22212D` | карточки |
| `--ink` / `--ink-2` | `#17171C` / `#858592` | `#F4F4F7` / `#9E9EAE` | текст |
| `--line` | `#EEEEF3` | `#262532` | границы |
| `--pa-clients` | `#F4E8FF` | `#2A2140` | категория «Клиенты» |
| `--pa-schedule` | `#FFF0E5` | `#33261E` | категория «Расписание» |
| `--pa-income` | `#FFF3DF` | `#332B1B` | категория «Доход» |
| `--pa-analytics` | `#EAF0FF` | `#1E2438` | категория «Аналитика» |
| `--t1` … `--t4` | `#3EBF8F` → `#E5595B` | те же | уровни напряжения |

**Типографика** — Inter, одна шкала на всё приложение:

| Роль | Размер |
|---|---|
| Большой заголовок экрана | 32 |
| Заголовок раздела | 22 |
| Заголовок карточки | 17–18 |
| Основной текст | 15–16 |
| Вторичный | 13–14 |

- Числа — `tabular-nums`, SemiBold.
- **Длинные имена не обрезаются.** Кегль сначала уменьшается (`fit()`), потом
  строка переносится. «Дмитрий Кова…» — это дефект, а не решение.
- **Радиусы** — 10 / 14 / 18 / 22 / 28 / 999.
- **Плотность** — меньше коробок: раздел это заголовок и воздух, список живёт
  прямо на фоне (`.rows.flat`), карточка появляется там, где содержимое правда
  отделено. Тени почти нет: карточка держится на границе `1px`.
- **Движение** — только `transform`/`opacity`, 140–320 мс, `prefers-reduced-motion`
  уважается.
- **Тач** — минимум 42–44 px; главные действия внизу, под большим пальцем.
- **Жесты** — свайп между днями в расписании, «потянуть, чтобы обновить».
- Градиент — только на одном действии экрана: hero-карточка и кнопка «+».

## Как это устроено

**Данные.** Одна база в `localStorage`: профиль, услуги, клиенты, записи,
заметки, отметки карты тела, абонементы. Первый запуск наполняется
демо-историей за четыре месяца — генератор детерминированный, расписание
считается от «сегодня», поэтому кабинет всегда выглядит живым.

**Числа не хранятся.** Доход, средний чек, загрузка, статистика клиента и
прогресс по зонам считаются из записей при каждом рендере — поэтому они не
могут разойтись с расписанием. Деньги считаются только по проведённым сеансам:
план — это ещё не доход.

**Карта тела.** Девять зон, четыре уровня напряжения. Каждая отметка — это
запись с датой, а не перезапись состояния: из них собирается история
(«поясница: сильное → среднее → лёгкое») — то, что показывает клиенту результат.

**AI-заметка.** Массажист диктует голосом (Web Speech API там, где браузер
умеет; иначе — набирает текст), разбор идёт **на устройстве**: зоны, сторона,
состояние, реакция, срок следующего сеанса. Без сети и без ключей — работает в
любом кабинете. Результат всегда правится руками: это черновик, а не приговор.

**Абонемент.** Оплата абонементом на экране завершения сеанса списывает один
сеанс и не добавляет денег второй раз — иначе доход считал бы одно и то же
дважды.

**Сравнение периодов честное.** 19 августа против полного июля — это не падение
на 57%, а половина месяца против целого. Прошлый период обрезается по тот же
день (`prevRange`), поэтому «−12% к прошлому месяцу» значит именно это.

**Сеанс — это сценарий, а не экран.** Таймер → зоны и диктовка по ходу →
разбор (зоны, интенсивность, заметка, оплата) → «Сеанс завершён» со стоимостью,
длительностью и предложением записать следующий визит через 7 или 14 дней.

## Проверки

```
node massage/tests/smoke.js
```

JSX из `index.html` транспилируется (`bun` или `@babel/standalone`) и
выполняется в песочнице с заглушкой React: каждый экран реально рендерится,
поэтому забытая переменная или битый экран видны сразу. Проверяются демо-данные,
деньги, свободные окна, статистика клиента, карта тела, разбор заметок,
действия над базой, таймер сеанса, хранилище, пустой кабинет и токены
дизайн-системы.
